# 2026-07-23 — v1.1.0: Requestly-Parity Rewrite (Groups G1–G8)

This release reworks SpliceTap from a single-mode API mocker into a six-type
request-manipulation tool with a v2 rule schema, a live DevTools log, and a
de-duplicated shared-module core. Summary by implementation group:

- **G1 — Shared modules + tests**: Extracted the placeholder engine, matcher,
  and JSON Merge Patch into three canonical UMD modules (`src/placeholders.js`,
  `src/matcher.js`, `src/patch.js`) that load in the MAIN world, the service
  worker, and Jest without diverging. Fixed the broken `require()`-on-ESM test
  setup (`src/index.js`); `src/utils.js` now delegates instead of duplicating.
  Added `tests/matcher.test.js` and `tests/patch.test.js`.
- **G2 — Interceptor rewrite** (`content/injected.js`): Removed the local
  matcher/placeholder copies; branched fetch and XHR handling by rule type
  (mock static/patch, block, delay, redirect); added the `logInterception`
  postMessage pipeline and the `x-splicetap` / `x-splicetap-rule` response
  headers. XHR matching moved into `send()` where headers/body are known.
- **G3 — Manifest + relay**: Switched to declarative MAIN-world injection via a
  `"world": "MAIN"` content_scripts entry (no more script-tag injection),
  added the `declarativeNetRequest` permission, removed `web_accessible_resources`,
  bumped version to 1.1.0, and simplified `content/content.js` to a pure relay.
- **G4 — Background**: Added `service_worker/dnr.js` (maps `headers`/`queryparams`
  rules to declarativeNetRequest dynamic rules and syncs them on every mutation),
  the 200-entry interception-log ring buffer, `normalizeRule`/`allocateDnrId`
  storage migration helpers, the new log message types, and the host-prefill
  context menu. Added `tests/dnr.test.js`.
- **G5 — Options editor**: Added the Rule Type selector and type-specific field
  groups, v2 schema build/load, per-type validation (including rejecting
  `match.headers`/`match.graphql` on DNR-backed types), the context-menu prefill,
  new templates (GraphQL Mock, Patch, Block, Redirect, CORS Unblock, User-Agent),
  and rule-type badges.
- **G6 — Popup**: Added type badges to rule rows and guarded the Test/display
  paths so v1 rules and non-mock types render without errors.
- **G7 — DevTools**: Deleted the dead `onRequestFinished` detection; added
  `devtools/panel.js` which polls `getInterceptionLog` every 2 s and renders the
  live interception log with an empty state and a working Clear button.
- **G8 — Docs + verification**: Rewrote README to describe the real two-mechanism
  architecture (MAIN-world fetch/XHR patching + declarativeNetRequest), all six
  rule types, patch-mode semantics, GraphQL matching, the full placeholder list,
  rule precedence, permissions, and the accepted limitations. Removed the false
  "DeclarativeNetRequest does the mocking" and Firefox-support claims. Added this
  changelog entry and the manual smoke-test checklist below.

# Manual Smoke-Test Checklist (v1.1.0)

Run after `Load unpacked` in chrome://extensions/ (Developer mode). These verify
behavior a headless test suite can't reach (a real Chrome loading the extension).

- [ ] Create one rule of each type via the options page (mock, block, delay,
      redirect, headers, queryparams) and confirm each saves and re-opens for
      edit with its fields intact.
- [ ] **Static mock**: trigger the matched request; confirm the response body is
      the mock body and the response carries an `x-splicetap: true` header.
- [ ] **Patch mock**: point a patch rule at a real JSON API; confirm exactly one
      field is altered (or deleted with `null`) and the rest of the real response
      is preserved.
- [ ] **Block**: confirm a matched `fetch` rejects (and XHR fires `error`).
- [ ] **Delay**: confirm the matched request is visibly delayed by `delayMs`,
      then completes normally.
- [ ] **Redirect**: confirm the request lands on the destination URL (test a
      `/regex/` pattern with `$1` capture too).
- [ ] **Headers**: confirm the added/removed header appears on a real request in
      the DevTools Network tab (e.g. a CORS `Access-Control-Allow-Origin: *`).
- [ ] **Query params**: confirm the added parameter appears on the outgoing
      request URL (and removed keys are stripped).
- [ ] **DevTools SpliceTap panel**: trigger a mocked call and confirm a row
      appears within ~2 s; confirm Clear empties the log.
- [ ] **Popup**: confirm the on/off toggle and per-rule enable toggles work and
      the rule list shows type badges.
- [ ] **Migration**: import a v1 (pre-`type`) rules JSON export and confirm the
      rules load and behave as `mock` rules.
