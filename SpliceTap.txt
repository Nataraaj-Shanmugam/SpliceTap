# Live API Mocking Browser Extension - Complete PRD & UI Specifications

## 🎯 Product Overview

### Core Value Proposition
**"Mock any API in 30 seconds, directly in your browser"**

A lightweight Chrome/Firefox extension that intercepts HTTP requests and allows developers to:
- Override API responses with custom data
- Simulate error conditions and network delays
- Modify specific JSON fields without replacing entire responses
- Test frontend behavior without backend dependencies

### Target Users
- **Frontend Developers** - Primary audience, need quick API mocking for development
- **Solo Developers** - Building full-stack apps, need to test UI before backend is ready
- **Students/Bootcampers** - Learning API integration without complex tooling


### Core Components
1. **Service Worker** - Intercepts requests via `chrome.webRequest` API
2. **Popup Interface** - Main rule management UI (400x600px)
3. **Context Menu** - Right-click on requests to create rules
4. **DevTools Panel** - Optional advanced rule editor
5. **Storage** - Chrome storage API for rule persistence
6. **Test Engine** - Built-in rule validation and testing system

## 🧪 Testing & Validation System

### Rule Testing Engine

#### 1. Test Button Functionality
When the "Test" button is clicked, the system performs:

```javascript
const testRule = async (rule) => {
  const testResults = {
    urlPattern: validateUrlPattern(rule.match.url),
    jsonSyntax: validateJson(rule.response.body),
    httpStatus: validateStatusCode(rule.response.statusCode),
    headers: validateHeaders(rule.response.headers),
    simulation: await simulateRequest(rule)
  };
  
  return {
    passed: Object.values(testResults).every(result => result.valid),
    results: testResults
  };
};
```

#### 2. Validation Types

**URL Pattern Validation:**
- Check regex syntax for regex patterns
- Validate wildcard patterns
- Test against sample URLs
- Warn about overly broad patterns

**JSON Validation:**
- Parse JSON for syntax errors
- Validate against JSON schema if provided
- Check for common JSON issues (trailing commas, etc.)
- Size validation (warn if > 1MB)

**HTTP Status Validation:**
- Ensure status codes are valid (100-599)
- Warn about unusual status codes
- Validate status text matches code

**Header Validation:**
- Check header name formatting
- Validate header values
- Warn about conflicting headers

**Simulation Testing:**
- Create mock XMLHttpRequest/fetch
- Apply rule transformation
- Verify response structure
- Test delay functionality

#### 3. Test Results Display

The test results panel shows:
- **Visual Indicators**: ✅ Pass, ❌ Fail, ⚠️ Warning
- **Error Messages**: Specific validation failures
- **Response Preview**: What the mocked response will look like
- **Performance Metrics**: Response time with delays
- **Recommendations**: Suggestions for rule improvements

#### Update Handling & Migration
```javascript
const handleExtensionUpdate = async (previousVersion, currentVersion) => {
  try {
    // Load existing metrics from cache folder
    const existingMetrics = await loadMetricsFromCache();
    
    if (existingMetrics) {
      // Migrate metrics to new version format
      const migratedMetrics = migrateMetrics(existingMetrics, currentVersion);
      
      // Add update record
      migratedMetrics.metadata.extensionUpdates.push({
        from: previousVersion,
        to: currentVersion,
        date: new Date().toISOString()
      });
      
      // Save updated metrics
      await saveMetricsToCache(migratedMetrics);
    } else {
      // Initialize new metrics file
      await initializeMetrics(currentVersion);
    }
  } catch (error) {
    console.warn('Failed to migrate metrics:', error);
    // Fallback: Initialize fresh metrics
    await initializeMetrics(currentVersion);
  }
};

const migrateMetrics = (oldMetrics, newVersion) => {
  // Version-specific migrations
  switch (newVersion) {
    case '1.2.0':
      // Add new testResults field if missing
      if (!oldMetrics.testResults) {
        oldMetrics.testResults = { passed: 0, failed: 0, averageTestTime: 0 };
      }
      break;
    case '2.0.0':
      // Major version migration - restructure data
      return restructureMetricsV2(oldMetrics);
    default:
      // Minor updates - no migration needed
      break;
  }
  
  // Update version and timestamp
  oldMetrics.metadata.version = newVersion;
  oldMetrics.metadata.lastUpdated = new Date().toISOString();
  
  return oldMetrics;
};
```

#### Cache Management
```javascript
const cacheManager = {
  // Write metrics to cache folder
  saveMetrics: async (metrics) => {
    const cacheDir = await getCacheDirectory();
    const filePath = `${cacheDir}/api-mocker-metrics.json`;
    await writeFile(filePath, JSON.stringify(metrics, null, 2));
  },
  
  // Read metrics from cache folder  
  loadMetrics: async () => {
    try {
      const cacheDir = await getCacheDirectory();
      const filePath = `${cacheDir}/api-mocker-metrics.json`;
      const data = await readFile(filePath);
      return JSON.parse(data);
    } catch (error) {
      return null; // File doesn't exist or corrupted
    }
  },
  
  // Clean up old metrics (privacy compliance)
  cleanup: async () => {
    const metrics = await this.loadMetrics();
    if (metrics) {
      // Remove data older than 30 days
      const thirtyDaysAgo = new Date(Date.now() - 30 * 24 * 60 * 60 * 1000);
      
      // Clean up daily data
      Object.keys(metrics.requestsIntercepted.daily || {}).forEach(date => {
        if (new Date(date) < thirtyDaysAgo) {
          delete metrics.requestsIntercepted.daily[date];
        }
      });
      
      await this.saveMetrics(metrics);
    }
  }
};
```
